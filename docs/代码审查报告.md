## 中等问题（建议修复）

### M1. 空查询排序的频率权重被时间戳淹没（逻辑 bug）
`Search.cs:83`
```csharp
return c * 10_000_000_000L + last;   // last = DateTime.UtcNow.Ticks ≈ 6.4e17
```
`Count * 1e10` 相对 Ticks（~6.4e17）完全可忽略：Count=100 也只贡献 1e12。
实际效果是「**最近使用**排序」而非设计的「(Count, LastTicks) 频率优先」。
一个昨天用过 1000 次的软件会排在今天刚用过 1 次的软件后面。
**修复**：`IdleCompare` 先比 `Count` 再比 `LastTicks`（不要拼进一个 long，会溢出）。
自检只测了带查询的频率加权（`r6`），没测空查询路径，所以没抓住——建议补断言。

### M2. 高 DPI 下初始窗口尺寸与布局度量不一致
`MainWindow.cs:60/105`、`HotkeyDialog.cs:41`
窗口按 `RecalcMetrics(1f)` 的 96 DPI 尺寸创建；`WM_CREATE` 里虽按真实 DPI
重算了 `_w/_h/_rowH` 等度量，但**从未把窗口 resize 到新尺寸**
（`ShowWin` 用 `SWP_NOSIZE`；`WM_DPICHANGED` 只在 DPI *变化* 时触发）。
主显示器缩放 ≠100% 时：列表底部行与底栏被裁剪、居中位置偏移。
本机恰好 96 DPI（自检输出可证），所以从未暴露。
**修复**：`OnCreate` 重算度量后 `SetWindowPos/MoveWindow` 到 `_w×_h`；HotkeyDialog 同理。

### M3. UWP 扫描的 20 秒超时形同虚设，可能永久卡死扫描线程
`Scanners.cs:250`
```csharp
string json = p.StandardOutput.ReadToEnd();      // 先无限阻塞
if (!p.WaitForExit(20_000)) { ... }              // 超时永远轮不到
```
powershell 若挂住且不关 stdout，`ReadToEnd` 无限阻塞 → 扫描线程卡死 →
`_scanning` 永远为 1 → 之后所有「重新扫描」被 `Interlocked` 挡掉，静默失效。
**修复**：stdout 也改 `ReadToEndAsync`，先 `WaitForExit(timeout)` 再取结果，超时 Kill。

### M4. RunSchtasks 重演坑 #18 的死锁反模式，且在 UI 线程同步执行
`AutoStart.cs:258-259`
```csharp
p.StandardOutput.ReadToEnd();
p.StandardError.ReadToEnd();   // 顺序读两条管道：stderr 写满即死锁
```
与 Scanners 里已修复并写进 AGENTS 坑 #18 的问题同款（schtasks 输出小，概率低但模式错误）；
`WaitForExit(timeout)` 同样排在 ReadToEnd 之后失效。
另外「开机自启诊断」菜单在 UI 线程同步调 `IsTaskRegistered()`（最长 8s）、
「注册登录自启任务」最长 10s——策略受限时界面会卡。
**修复**：stderr 并行读；UI 线程上的 schtasks 调用尽量缩短超时或移后台。

### M5. 托盘图标不处理 TaskbarCreated，explorer 重启后永久丢失
`Tray.cs`（全仓 grep 无 `TaskbarCreated`/`RegisterWindowMessage`）。
explorer 崩溃/重启后托盘图标消失，且不会重建。
**修复**：`RegisterWindowMessage("TaskbarCreated")`，主窗口收到后重新 `NIM_ADD`。
